### AETHER_* 标记协议
- 定义：AI Agent 与编辑器之间的文本工具调用协议，所有标记必须独占整行并以 `AETHER_` 前缀开头，避免与 Git 冲突标记混淆。包括 `AETHER_FILE`/`AETHER_RUN`/`AETHER_READ`/`AETHER_LIST`/`AETHER_PLAN`/`AETHER_LOCATE`/`AETHER_EDIT` 及其对应的结束标记，用于让 AI 模型以纯文本形式表达文件编辑、终端执行、只读探查、规划任务等动作，再由编辑器解析并回喂结果形成闭环。
- 别名：AETHER_FILE、AETHER_RUN、AETHER_READ、AETHER_LIST、AETHER_PLAN、AETHER_LOCATE、AETHER_EDIT、AETHER_SEP、AETHER_END_*

### Ask / Agent 模式
- 定义：两种 AI 交互模式：Ask 为普通问答，不注入操作协议；Agent 模式会在系统提示词中注入文件/终端操作协议（AETHER_* 标记），使模型能主动执行工作区文件修改、终端命令等动作，并通过 READ/LIST/RUN 等工具回喂形成 agent loop（最多 5 轮）。
- 别名：ask 模式、agent 模式

### CoT 多任务编排流水线
- 定义：当 Agent 回合输出包含 `AETHER_PLAN` 清单时触发的多任务执行流程：将裸标记块改写为可读执行计划，建立 `AgentPipeline{goal, tasks, cursor, created_files}`，逐任务推进——RUN 任务直接执行，FILE 任务发起聚焦独立调用（仅最小上下文，避免爆上下文窗口），完成后落盘并推进下一任务。
- 别名：agent pipeline、CoT 流水线

### 三阶段持久化
- 定义：对话数据的分层存储策略：热数据用 HotDataStore（内存完整会话 + mmap 追加日志 `conversations/hot/<id>.log`，崩溃可恢复）；温数据由后台归档线程写入 AetherDB（`aether_memory.aedb`，HNSW 向量索引+混合检索），归档成功后删除热日志；冷数据经 ACE Reflector 反思沉淀策略条目，启动时 grow-and-refine 保守剪枝。不活跃会话两阶段休眠卸载内存。
- 别名：hot/warm/cold 存储、会话归档

### 欢迎页模式（welcome_mode）
- 定义：无工作区启动时的 UI 状态标志。进入该模式时活动栏/侧边栏不渲染，但布局层 `editor_region()` 不再扣除左侧栏宽度，底部面板等 20 处调用点自动一致；每帧由渲染层同步 `self.ui.layout.welcome_mode = showing_welcome`。有工作区场景下该标志为 false，行为不变。
- 别名：welcome_mode、welcome page

### 默认启动模式
- 定义：设置页通用页中的「默认启动模式」行，点击切换 `ui.editor_mode`（developer ↔ agent），立即保存至 settings.json，重启后生效。智能体模式下齿轮按钮统一打开标签页而非弹窗，并在首次显示时自动展开右侧面板以承载设置内容。
- 别名：default launch mode、editor_mode

### 信任检查（check_workspace_trust）
- 定义：打开工作区时的模态信任对话框机制。若工作区路径不在信任列表中会弹出确认框，阻塞启动流程直到用户确认或拒绝。测试中曾误判为 sidebar 注册延迟，实际是信任对话框导致 open_folder 阻塞约 11 秒。
- 别名：workspace trust、trusted_folders

### 命中区（hit region）
- 定义：Win32/Direct2D 渲染层注册的语义可点击区域，如 `titlebar:bottom_panel`、`settings:default_mode`、`sidebar:new_file`、`settings_tab:*` 等。测试框架通过 `Wait-AetherHitRegion` 等待并按名称触发点击；jsonl 文件中按帧累积命中坐标，用例启动前需清理以防旧帧污染断言。
- 别名：hit region、hit regions、Wait-AetherHitRegion

### last_workspace
- 定义：设置项，主窗口启动时自动恢复上次工作区。自动化用例需在启动前清空该值以确保进入欢迎页，否则会出现假 PASS（采样到的是侧边栏背景色而非欢迎页）。
- 别名：last workspace

### 流式中断抢救（salvage_ai_partial_edits）
- 定义：AI 生成被中断时的容错机制：完整 FILE 块照常落盘，未闭合的「新建文件」块抢救已生成的部分内容并提示可能不完整；修改/删除类截断块与 RUN 命令不抢救以防破坏。
- 别名：partial edits salvage、中断抢救

### 思考模式超时阈值
- 定义：AI 请求的首包超时看门狗在 thinking=true 时放宽至 180s（非思考模式仍为 30s），因为 DeepSeek v4-flash + reasoning_effort=max 的 prefill + 思考启动首包延迟经常超过 30 秒。首个 reasoning/token 到达后看门狗失效，后续流式不受影响。
- 别名：thinking timeout、first packet watchdog
