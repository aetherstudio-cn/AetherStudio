# 文件树初始加载采用分层预展开策略

_来源：6c76640 → 9265868 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
打开文件夹时，`scan_file_tree_entries` 仅扫描根目录直接子项，导致 depth==0 的目录虽标记 `is_expanded=true` 但内容为空；嵌套目录需等父目录加载完成后由用户手动展开才触发加载，形成级联等待。同时 `preload_expanded_dirs` 依赖 16ms 定时器周期串行触发，进一步放大延迟。

## 决策驱动
- 减少首屏空白时间
- 避免嵌套目录级联等待
- 保持 UI 线程响应性

## 备选方案
- **初始扫描递归到多层** _（已否决）_ — 优点：一次性加载更多节点；缺点：UI 线程阻塞风险高，大项目可能卡顿
- **保持现有 16ms 定时器逐批加载** _（已否决）_ — 优点：实现简单、对 UI 影响小；缺点：嵌套展开场景存在明显延迟，用户体验差
- **初始扫描后同步加载一层 + 立即触发预加载** — 优点：根层子节点立即可见，嵌套目录在父目录完成后快速加载，兼顾性能与响应性；缺点：需在 `on_folder_scan_batch_ref` 和 `on_subdir_scan_result` 两处协调调用预加载逻辑

## 决策
在 `on_folder_scan_batch_ref` 完成初始扫描后，对 root 层已展开目录同步调用 `populate_children_one_level` 加载一层子节点；随后立即调用 `state.preload_expanded_dirs()` 启动嵌套目录的异步预加载，并在 `on_subdir_scan_result` 末尾追加一次预加载以消除定时器周期延迟。

## 影响
打开工作区后根层子目录即时可见，嵌套展开目录不再出现长时间空白；但仍依赖 16ms 定时器处理深层嵌套，极端深树结构仍有轻微延迟。`file_type()` 系统调用开销经评估非主要瓶颈，未做改动。
